# PrintGo Architecture & Implementation Log
**Date:** March 13, 2026

## 1. WebSocket & Server Refactoring
- **Single Admin Architecture:** Simplified the admin WebSocket connection model. Instead of an `adminSockets` map, we now maintain a single `adminState` object. If a new admin connects, the previously connected admin is automatically disconnected (`admin-replaced` event).
- **Removed `shutdownSystem`:** The `shutdownSystem` command, previously deemed dangerous, has been fully stripped from the `agent.service.js`, `admin.handler.js`, and `index.js`.
- **Refactored `kioskSockets` Storage:** Kiosks' socket storage array now tracks `kiosk`, `agent`, `userSessionUUID` and `lastSeen`.
- **Unhandled Promise Rejections Fix:** Corrected async issues by adding `.catch()` chains to incoming WebSocket connection promises.

## 2. Kiosk Database Schema (MongoDB Migration)
- **Shift from PostgreSQL to MongoDB:** Original plans for a `Kiosk` table in PostgreSQL (Prisma) were reconsidered. The relational mapping between `NoAuthUser` and `Kiosk` was decoupled in `schema.prisma`.
- **Creation of `kiosk.model.js`:** The schema was implemented entirely via Mongoose for nested, document-style management, including:
  - **Core Identity:** `kioskId`, `kioskName`, `isActive`, `newConnection`, `currentOwner`.
  - **Location Details:** Nested object for `region`, `city`, `address`, `landmark`, `pincode`, and `coordinates`.
  - **Printers Configuration:** Isolated and specific nested sub-documents for `bw` (Black & White) and `color`, tracking `name`, `model`, `status`, `paperAvailable`, `inkLevel`, `supportedFormats`, and `pricePerPage`.
  - **Machine Details:** Automatically populated properties such as `hostname`, `platform`, `arch`, `ipAddress`, OS `capabilities`, and `status`/`lastSeenAt`.
  - **Metrics & Configuration:** Tracking lifetime and chronological revenue, plus generic configuration like `maxFileSizeMB` and `supportedFileTypes`.

## 3. Dynamic Kiosk Verification & Telemetry
- **On-the-fly Database Registration (`validateKioskId.js`):** Removed the hardcoded list of valid kiosk IDs. Now securely looks up connections in MongoDB via `Kiosk.findOne()`.
- **Auto-Discovery of New Kiosks:** If an unrecognized Kiosk tries to connect, it's not rejected; instead, it is safely auto-created in MongoDB with `isActive: false` and `newConnection: true`. This allows it to persist on the network while waiting for manual review from an Admin.
- **Automated Machine Details Populating (`agent.handler.js`):** 
  - On the `agent-ready` event, MongoDB is dynamically updated with the agent's OS metrics (hostname, arch, platform, capabilities) via Mongoose.
  - On the 20-second `agent-heartbeat` event, the machine's `<lastSeenAt>` timestamp is continuously updated.
  - Gracefully records `status = offline` upon disconnection.

## 4. Admin Authentication Implementation
- **MongoDB Schema (`admin.model.js`):** Includes `username`, `email`, `password` (hashed via bcrypt), `role` (`superadmin`, `service_person`), and `isActive` checks.
- **Auth Endpoints:** Created an `admin.auth.controller.js` to manage `/auth/register`, `/auth/login`, and `/auth/logout`, securely verifying JSON Web Tokens (JWT).
- **Route Protections (`admin.routes.js`):** Enforced a lightweight JWT verification middleware `protectAdmin` on sensitive API endpoints.
- **WebSocket Auth (`connectionRouter.js`):** Any connection establishing `role=admin` must pass a valid URL `?token=...` parameter. It is verified live using JWT against the `JWT_SECRET`. Unauthorized connections are immediately killed.

## 5. Next-Gen Admin Control Panel
We rebuilt the traditional admin system directly into the React-based Frontend using specialized hooks (`useAdminAuth`, `useAdminSocket`) and dynamic data presentation.

### Interactive Components & Pages:
- **`AdminAuthContext` & `AdminSocketContext`:** Cross-app React contexts holding live WebSockets (synced with JWT) & authentication state to allow rapid API queries.
- **Dashboard (`AdminDashboardPage.tsx`):**
  - KPI Blocks: Total Kiosks, "New Approvals" (highlighted), Inactive (attention required), Active.
  - Grouped mapping links (e.g. Regions index showing dynamically mapped DB entries like "Maharashtra").
  - Categorized list-view panels allowing administrators to jump straight into configuring a pending or problematic kiosk.
- **Region filtering (`AdminRegionPage.tsx`):** Easily pull kiosks associated specifically within targeted regions.
- **Live AWS-Style Configuration Details (`AdminKioskDetailPage.tsx`):** Interactive edit page leveraging `PATCH /admin/kiosks/:kioskId`.
  - **Status & Operations Block:** Switches to configure flags for `isActive` and `newConnection`. Immediately updates MongoDB.
  - **Geographical Block:** Real-time updates for location.
  - **B&W + Color Printer Nodes:** Separated forms enabling easy definitions for `OS Name`, `Display Model` and `Price Per Page`. 
  - **Live Command Binding:** Quick actions included inside blocks to execute WS requests straight to physical machines (`Sync Hardware`, `Test Print`, `Restart Services`).
- **Web-based Terminal Embed (`xterm.js`):**
  - Admins can instantly open an integrated Terminal tunnel via WebSocket directly to a remote kiosk without leaving the detail page.
