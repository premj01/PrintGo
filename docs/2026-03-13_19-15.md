# System Debugging - Admin Kiosks 500 Error Fix
**Date**: 2026-03-13
**Time**: 19:15

## Issue Overview
The Admin Dashboard was failing to load the kiosk list, repeatedly logging `GET http://localhost:3000/admin/kiosks 500 (Internal Server Error)`. This prevented the admin from viewing or managing any connected kiosks.

## Root Cause Analysis
The investigation identified several potential causes for the `500` error in the `admin.routes.js` file:
1.  **JSON Serialization Hazard**: The route was attempting to include `userSessionIdWithKioskId` from the `runtimeStore.js`. This object is part of the live runtime state and could contain non-serializable data (like `BigInt` or `Map` placeholders) or be subject to race conditions during serialization.
2.  **Insufficient Error Handling**: The original code lacked detailed logging and safe property access for `dbKiosk.kioskId`, which could lead to unhandled crashes if database records were slightly inconsistent with memory state.
3.  **Redundant Data**: The `userSessionIdWithKioskId` object was being sent to the client but was not used by the frontend `AdminDashboardPage.tsx`, making its inclusion an unnecessary risk and security leak.

## Resolution Steps

### 1. Backend Route Refactoring
Modified `server/src/modules/admin/admin.routes.js` to improve stability and security:
- **Cleaned Response**: Removed `userSessionIdWithKioskId` from the JSON response.
- **Added Safety Checks**: Implemented more robust property checking when merging database kiosk data with live socket status.
- **Enhanced Logging**: Added `console.error` blocks to catch and log specific database or runtime errors instead of failing silently with a generic 500 message.

### 2. Robustness Upgrades
Applied similar improvements to other admin endpoints:
- `GET /admin/kiosks/:kioskId`: Added safety wrappers for socket status lookups.
- `PATCH /admin/kiosks/:kioskId`: Added body validation to prevent accidental mutation of sensitive fields.

### 3. Verification & Cleanup
- Created and used a `test_server.js` on port `3002` to verify the fix independently of the main running process.
- Confirmed that `curl` requests with valid JWT tokens now return the correct kiosk list without errors.
- Cleaned up temporary debug logs and test scripts.

## Current System State
- **Backend**: Updated with robust admin routes.
- **Admin Dashboard**: Now successfully fetches the kiosk list from the API.
- **Security**: Reduced data leakage by keeping session mapping internal to the server.

> [!NOTE]
> The server was restarted to apply these changes. Old debug logs indicating "DEBUG: GET /kiosks called" may still be visible in historical output but have been removed from the final code.
